## 5. Parser behaviour (`VoiceIntentParser`)

- Normalises case, whitespace, punctuation and apostrophes.
- Result is a `ParsedIntent`: `Status` (Ok / Empty / Unknown / Negated / Ambiguous), `Kind`, `TargetName`, `DestinationName`, `Direction`, `ParseScore`, `Error`.
- **Only `Status == Ok` is actionable** (`IsActionable`). Negated phrases ("do not release", "never release") and multi-action phrases ("select and release") are rejected, as are unknown and empty input. "never mind" is Cancel, not a negation.
- `TargetName`/`DestinationName` are `null` for deictic words ("that", "there"): meaning *use the gaze*. A consumer must still confirm a gaze target.
- **`ParseScore` is a text-match heuristic, not an acoustic or recognizer confidence.** It must never be compared with a speech threshold such as the starter's `confidenceThreshold = 0.75`.
- Limitations: fixed English vocabulary; no handling of speech errors, accents, or compound commands; "reset" only has a parser meaning (what it does to the scene is undefined, PENDING CONFIRMATION); named targets/destinations are strings and are not resolved to objects.

## 6. Desktop voice input (`DesktopVoiceInput`)

- **Real speech path (Windows Editor/Standalone only):** `KeywordRecognizer` over `VoiceIntentParser.KeywordGrammar`. Off until `F9` is pressed (or `listenOnStart`); an on-screen banner shows "LISTENING - MICROPHONE ON". No audio is recorded or saved by this code. Recognizer is disposed and unsubscribed in `OnDisable`/`OnDestroy`. Start-up failures (no speech support, no microphone, exception) set a visible error state and never throw.
- **Fallback (SIMULATED, NOT SPEECH):** keys 1–7 and a typed-text box (`F8`). Always labelled in the banner and in log lines.
- **Separate notions:** recognizer confidence (categorical, from the recogniser; `null` for fallback), parse result, and execution status. The component never executes anything (`ExecutionStatus.NotAttempted`).
- **Timestamps:** `ReceivedRealtimeS`, `ReceivedUtc`, measured `ParseDurationMs`, and `SpeechEndToEventMs` (recognizer-reported end of speech to event delivery; NaN for fallback). This is **not** an end-to-end latency and has not been validated. **No sub-350 ms claim is made.**
- **Not tested with a real microphone.** Android builds contain only the fallback; this says nothing about Quest voice.
- Not wired to the professor's controller. Forwarding to `OnVoicePhraseDetected` would make keyboard input look like voice, so it was deliberately not done.

## 7. Telemetry schema and mapping (PROPOSED, PENDING CONFIRMATION)

### Per-trial file `trials_<origin>_<sessionId>[_n].csv` (25 columns)
`schema_version, data_origin, session_id, participant_pseudonym, condition, trial_index, trial_id, start_utc, end_utc, target_name, action, outcome, failure_reason, error_count, input_modality, target_distance_m, target_width_m, fitts_id_bits, movement_time_raw_s, movement_time_used_s, mt_safeguard_applied, throughput_bps, recognition_latency_ms, command_text, fitts_note`

Rules enforced by `TrialRecord.Validate()` and `TrialCsvWriter`:
- `data_origin` ∈ `real | selftest | simulated`. `real` requires pseudonym `P01`–`P999`; `selftest` requires `SELFTEST`; `simulated` requires `SIM`. Names, roll numbers (e.g. A057) and emails are rejected.
- `condition` ∈ `controller | gaze_voice`. Gaze-dwell is not accepted (optional, not an approved core condition).
- A failed/cancelled trial needs a `failure_reason`; latency is accepted only for `Voice` input.
- Invalid geometry or movement time leaves ID/TP blank and writes the reason in `fitts_note`. Raw and safeguarded MT are both written (`mt_safeguard_applied`). Throughput is blank for non-success trials.
- Files are created with `FileMode.CreateNew`; a name collision gets `_2`, `_3`…; invariant culture; UTF-8 without BOM; failures return `false` with `LastError`.

### Frame-level file
Not implemented in this phase. The starter logger keeps its 7 columns (`timestamp_s, target_dist_m, target_width_m, fitts_id_bits, elapsed_mt_s, nlp_latency_ms, has_gaze_focus`). Proposed additions when it is replaced or wrapped: `session_id, participant_pseudonym, condition, data_origin`. **90 Hz is not verified:** the starter logger samples inside `Update`, so the real rate follows the frame rate.

## 12. Known limitations and risks

- Foundation not integrated: no scene, no gaze loop, no interaction state machine, no snapping, no reticle, no highlight in a running scene.
- Parser vocabulary is fixed and English; `reset` semantics are undefined.
- Keyword recognition is grammar-constrained, not open dictation, and only on Windows.
- `ParseScore` is heuristic; recognizer confidence is categorical and desktop-only.
- Schema is a proposal; renaming it later would break any CSVs already written.
- The professor's figures are Git LFS pointer files; figures cannot be viewed or regenerated from real data yet.
- `Packages/` and `ProjectSettings/` are untracked until the team decides to commit them.
